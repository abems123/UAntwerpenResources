# Tijdscomplexiteit — Exam Summary

*(Sipser, Introduction to the Theory of Computation, Ch. 7)*

## 1. PTIME

**DTIME.** $\text{DTIME}(t(n)) = \{L \mid L$ is decided by a deterministic TM in time $O(t(n))\}$.

**PTIME.** $\text{PTIME} = \bigcup_k \text{DTIME}(n^k)$ — languages decidable in polynomial time. This is the formal notion of "efficiently solvable."

**Encoding matters:** input size = number of *bits*, not the numeric value. An algorithm polynomial in the *value* of a number can still be exponential in its *bit-length* (e.g. trial division for primality).

**Worked examples:**
- **PATH** (is there a path from $s$ to $t$ in graph $G$?): solved via **BFS** in polynomial time.
- **RELPRIME** ($\gcd(x,y)=1$?): solved via **Euclid's algorithm**; number of iterations is polynomial in the *bit-length* of the inputs (each step at least halves one number).
- **PRIMES**: historically shown to be in PTIME (deep result, statement only).

## 2. Satisfiability

- **Syntax/semantics** of propositional logic; a formula $\varphi$ is satisfied by assignment $\nu$ if $\nu \models \varphi$.
- **CNF (Conjunctive Normal Form):** AND of ORs of literals. Every formula can be converted to CNF; using extra variables keeps the conversion **polynomial in size**, but only preserves **equisatisfiability** (same satisfiability), not logical equivalence.
- **SAT** = satisfiable propositional formulas. **CNF-SAT** = SAT restricted to CNF formulas. **3SAT** = CNF-SAT with exactly 3 literals/clause. **2SAT** = exactly 2 literals/clause. **HORN-SAT** = clauses with at most one positive literal.

**2SAT algorithm:** build an implication graph (literal $\to$ literal edges from each clause); $\varphi$ satisfiable $\iff$ no variable $x$ has $x$ and $\neg x$ in the same **SCC** (strongly connected component). Polynomial via SCC computation.

**HORN-SAT algorithm:** unit propagation — repeatedly force any single-literal (unit) clause true, propagate, until no more propagation is possible or a contradiction is found. Polynomial.

## 3. NP

**Verifier.** A TM $V$ such that $L = \{w \mid V$ accepts $\langle w,c\rangle$ for some certificate $c\}$, running in time polynomial in $|w|$.

**NP** = languages with a polynomial-time verifier.

**Equivalent view (NTM):** $L\in NP \iff L$ is decided by a **nondeterministic** TM in polynomial time (guess certificate $c$ nondeterministically, then check it deterministically). Proof of equivalence goes both ways:
- verifier $\to$ NTM: guess $c$ (bounded length $d\cdot n^k$, since $V$ can't use more), simulate $V$.
- NTM $\to$ verifier: let $c$ = description of which nondeterministic branch was taken; $V$ simulates that one branch deterministically.

**NTIME.** $\text{NTIME}(t(n))$, and $NP = \bigcup_k \text{NTIME}(n^k)$.

**Landscape:** $\text{PTIME} \subseteq NP \subseteq \text{EXPTIME}$ (brute-force simulate NTM: try every branch $\Rightarrow$ exponential). Whether $\text{PTIME}=NP$ is **open** (Millennium Prize Problem).

**Examples:** CLIQUE (certificate = the $k$ vertices), HAMPATH (certificate = the path), SAT (certificate = satisfying assignment).

## 4. Reductions, Hardness, Completeness

**Poly-time reducibility.** $A \le_P B$: exists poly-time computable $f$ with $w\in A \iff f(w)\in B$. Reductions **compose**: $A\le_P B, B\le_P C \Rightarrow A\le_P C$.

**NP-hard:** $B$ is NP-hard if $A\le_P B$ for **every** $A\in NP$.
**NP-complete:** $B\in NP$ **and** $B$ is NP-hard.

**Key propagation rule:** if $A$ is NP-complete and $A\le_P B$ (with $B\in NP$), then **$B$ is NP-complete too**. This is why, once you have one NP-complete problem, you only need *one* reduction *into* each new problem — not a reduction from every NP problem.

**Worked reduction — $3SAT \le_P CLIQUE$:** from formula $\varphi=C_1\wedge\dots\wedge C_k$ (3 literals/clause), build graph $G$: one group of 3 vertices per clause (labeled by its literals); edge between two vertices unless (a) same group, or (b) contradicting literals ($x$ vs $\neg x$). Then $\varphi$ satisfiable $\iff$ $G$ has a $k$-clique (pick one satisfying literal/vertex per clause/group).

## 5. Cook–Levin Theorem

**Theorem:** SAT is NP-complete. (SAT $\in NP$ shown earlier; the real content is NP-hardness — **every** $A\in NP$ reduces to SAT.)

**Proof idea — the tableau:** take NTM $N$ deciding $A$ in $\le n^k$ steps. A **tableau** is an $n^k\times n^k$ grid where row $i$ = the tape configuration of $N$ at time $i$. $N$ accepts $w$ $\iff$ some accepting tableau exists.

**Encode the tableau as a SAT formula.** Variable $x_{i,j,s}$ = "cell $(i,j)$ contains symbol $s$." Build $\varphi = \varphi_{cell}\wedge\varphi_{start}\wedge\varphi_{move}\wedge\varphi_{accept}$:
- $\varphi_{cell}$: every cell has **exactly one** symbol.
- $\varphi_{start}$: row 1 = the real starting configuration of $N$ on $w$.
- $\varphi_{accept}$: some cell in the grid holds the accept state.
- $\varphi_{move}$: every $2\times3$ **window** (3 cells + the 3 cells below them) is *legal*, i.e. consistent with $N$'s transition function $\delta$. Checking only local $2\times3$ windows suffices because the TM head changes only a small local region each step — proven by contradiction (first illegal transition forces a legal window to be violated).

**Correctness:** $\varphi$ satisfiable $\iff$ an accepting tableau exists $\iff$ $N$ accepts $w$.

**Size:** all four sub-formulas are $O(n^{2k})$ in length (constant alphabet/state-set size, fixed transition table) $\Rightarrow$ $f$ is a valid polynomial-time reduction. $\blacksquare$

## 6. NP-Complete Problems (reduction web)

Chain built from SAT outward, each step using the propagation rule above:

**SAT $\le_P$ CNF-SAT:** direct — the standard CNF-conversion algorithm *is* the reduction.

**CNF-SAT $\le_P$ 3SAT:** shrink long clauses using new "relay" variables $z_1,\dots$, chaining 3-literal clauses so satisfiability is preserved (one clause more than the number of $z$'s guarantees an original literal must do the satisfying work in the reverse direction).

**3SAT $\le_P$ CLIQUE** (above) **$\Rightarrow$ CLIQUE is NP-complete.**

**CLIQUE $\le_P$ VERTEX-COVER:** via the complement graph $\bar G$: $C$ is a $k$-clique in $G$ $\iff$ $V\setminus C$ is a $(|V|-k)$-vertex cover in $\bar G$.

**3SAT $\le_P$ HAMPATH:** each variable $\to$ a "diamond" gadget traversable in 2 directions (true/false); each clause $\to$ a single vertex, reachable via a detour only in the direction matching a satisfying literal.

**HAMPATH $\le_P$ UHAMPATH** (directed $\to$ undirected): split each vertex into $u_{in},u_{mid},u_{out}$ to simulate direction with undirected edges.

**UHAMPATH $\le_P$ UHAMCIRCUIT:** add one new vertex connected to $s$ and $t$, closing path into a cycle.

**UHAMCIRCUIT $\le_P$ TSP:** complete the graph; cost 0 for real edges, cost 1 for added edges, target $k=0$.

**3SAT $\le_P$ SUBSET-SUM:** numbers encode variable-choice digits + clause-satisfaction digits (target 1 per variable, 3 per clause; clause slack filled by dummy pairs $g_j,h_j$).

**SUBSET-SUM $\le_P$ PARTITION:** add two balancing numbers $y_1=2\sum_S x - t$, $y_2=\sum_S x+t$ so an equal split corresponds exactly to a target-$t$ subset.

**SUBSET-SUM $\le_P$ Integer Programming (IP):** trivial — a subset-sum instance already *is* a one-equation 0/1 integer program.

## 7. coNP

Complement of a language: flip yes/no (e.g. UNSAT vs SAT). **NP $\in A$ does not imply $\bar A \in NP$** (verifying "no solution exists" isn't obviously easy). $\text{coPTIME}=\text{PTIME}$. $\text{PTIME}\subseteq NP\cap\text{coNP}$. Whether $NP=\text{coNP}$ is open.

## 8. Reductions & PTIME — why NP-completeness matters

**Proposition:** $A\le_P B$ and $B\in\text{PTIME}$ $\Rightarrow$ $A\in\text{PTIME}$.

**Consequence:** a poly-time algorithm for **any single** NP-complete problem would force $\text{PTIME}=NP$ — this is exactly why NP-completeness is the standard tool for probing that open question.

**Cautionary note:** defining "PTIME-complete" the same way is **useless** — with poly-time reductions, *every* nontrivial language in PTIME becomes "PTIME-complete" (the reduction can just decide $B$ itself and output one of two fixed dummy values). Poly-time reductions are too powerful to distinguish structure *inside* PTIME — only useful at the NP level and above.
