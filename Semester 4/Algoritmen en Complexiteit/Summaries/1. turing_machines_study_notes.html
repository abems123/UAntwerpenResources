1 · Deterministic Turing Machines

slides II-3–21 · Sipser §3.1

The base model everything else in the course extends. A TM = finite control + infinite tape + head + accept/reject states. Church-Turing thesis: algorithm = Turing machine.

Definition — the 7-tuple

M = (Q, Σ, Γ, δ, q₀, q_accept, q_reject)

  • Q: finite states · Σ: input alphabet, ⊢,⊔∉Σ · Γ: tape alphabet, Σ∪{⊢,⊔}⊆Γ
  • δ : Q×Γ → Q×Γ×{←,□,→} — a partial function. δ(q,a)=(q′,b,D): write b, move per D, switch to q′.

Doesn't quite match Sipser 1-for-1

  • Sipser's δ only has {L,R} — no "stay" (□). It's a convenience: simulate it with one extra state.
  • Sipser has no ⊢ symbol — he just says "stay put if you'd move off the left edge." This deck uses a real left-marker instead: ⊢ sits at position 0, can't be overwritten, can't be passed.

Configurations: state + tape + head position, written as one string C = ⊢uqv (head sits on v's first symbol). Leads-to: for a,b,c∈Γ, u,v∈Γ*, qᵢ,qⱼ∈Q — uaqᵢbv leads to uqⱼacv (←), uacqⱼv (→), or uaqⱼcv (□), depending which of the three δ(qᵢ,b) gives. Start config on w: ⊢q₀w. q_accept/q_reject are halting states.

Worked example — even number of 0's

δ(q0,0)=(q1,⊔,→) · δ(q0,1)=(q0,⊔,→) · δ(q1,0)=(q0,⊔,→) · δ(q1,1)=(q1,⊔,→) · δ(q0,⊔)=(accept,⊔,→) · δ(q1,⊔)=(reject,⊔,→)

q0 = "even 0's so far" (also the start state), q1 = "odd". 1's don't change state; 0's flip it. Blanking as you go means the head only ever moves right.

Acceptance: chain C₁,…,Cₖ, C₁ the start config, each leads to the next, Cₖ accepting. L(M) = {w ∈ Σ* | M accepts w}. A language is Turing-recognizable if some TM accepts it — e.g. A_TM (recognizable but not decidable — proved in Machines en berekenbaarheid, assumed background here).

2 · Algorithms & Deciders

slides II-22–26 · Sipser §3.3

Definition

Algorithm = TM that halts on every input = a decider. A language is Turing-decidable (recursive) if a decider accepts it. From here on: every TM we discuss is assumed to be a decider.

Second example — palindrome decider Mp

  1. Empty word → accept.
  2. Remember first symbol, blank it, scan to the end.
  3. If last symbol matches, blank it too — else reject.
  4. If nothing's left (blank to the left of head) → accept.
  5. Else, return to just after where this pass started, repeat.

This is the machine used as the running example for the rest of the chapter — it's a decider because each round strips 2 symbols, so it can't run forever.

3 · Time Complexity

slides II-27–32 · Sipser §7.1

Definitions

  • step of M = one instruction of δ executed
  • time_M(w) = number of steps M takes on w
  • t_M(n) = max{ time_M(w) : |w|=n } — worst case over all inputs of length n

Mp re-analyzed step by step: empty-check (1) + scan-to-end (n) + compare (1) + mismatch-check (1) + scan-back (n), repeated n/2 times → t(n) ≤ (n/2)(2n+2) = n²+n. Quadratic — and (spoiler for part 6) that's basically unavoidable on one tape.

4 · Asymptotic Analysis

slides II-33–36 · Sipser §7.1

Big-O / Big-Ω / Big-Θ

  • O (upper bound): f(n)=O(g(n)) if ∃c,n₀: ∀n≥n₀, f(n) ≤ c·g(n)
  • Ω (lower bound): f(n)=Ω(g(n)) if g(n)=O(f(n)) — just the reverse of O
  • Θ (tight): both O(g(n)) and Ω(g(n)) at once (mentioned elsewhere, not this slide)

Mp once more, now in O-notation: steps 1/3/4 cost O(1), steps 2/5 cost O(n), repeated O(n) times → O(n)·O(n) = O(n²). Definition: M runs in time O(t(n)) if t_M(n) is of order O(t(n)). So: Mp runs in O(n²).

5 · Decision Problems

slides II-37–43

Definition

Decision problem for L: given w∈Σ*, decide yes/no whether w∈L. Complexity of a language: L is decided by M in O(t(n)) if L=L(M) and t_M(n)=O(t(n)) — this becomes a property of the problem, not of one machine.

Careful phrasing

"Efficient" = polynomial time (defined properly in the next file). The slide states flatly that SAT "can't be solved efficiently" — really shorthand for SAT is NP-complete, and believed (not proven) to have no polynomial algorithm. P vs NP is still open.

ConceptFormalized as
ProblemDecision problem — is w∈L?
AlgorithmDecider — a TM that always halts
ComplexityAsymptotic complexity — steps, cells used, ...

TMs can also compute functions (one q_halt instead of accept/reject, output = tape up to first blank) — mentioned, not the course's focus. Church-Turing thesis: all these TM variants have equal power. But not equal speed — which is exactly why parts 6 and 7 exist.

6 · Multi-tape Turing Machines

slides II-44–80 · Sipser §3.2 / §7.1

The longest, densest part of the deck. Same tuple, vectorized over k tapes: δ: Q×Γᵏ → Q×Γᵏ×{←,□,→}ᵏ. Only tape 1 gets the input; all k heads start at position 1.

Payoff — 2-tape palindrome decider in O(n)

Copy tape1→tape2 (O(n)) · reset head 1 to the start (O(n)) · move head 1 right / head 2 left together, comparing (O(1) × O(n)) · accept once they meet. Total: O(n) — versus O(n²) on one tape.

Theorem (power): anything decidable by a k-tape TM is decidable by a 1-tape TM. Simulation idea (formal transition tables skipped — not exam-expected, just the idea): lay the k tapes end-to-end on one physical tape, separated by real # symbols; mark head positions with "tilde" copies of symbols; scan once to read all k heads into the state, scan again to write + shift + move; repeat.

Theorem (cost)

k-tape O(t(n)) (t(n)≥n) ⟹ 1-tape O(t(n)²). Why: init O(n); per simulated step, two full passes of O(t(n)) each (only O(t(n)) cells are ever touched); k is constant. O(t(n))·O(t(n)) = O(t(n)²).

Can this be avoided? No — proved with palindromes again: 2 tapes give O(n), but any 1-tape TM needs Ω(n²), via crossing sequences (the one "Te kennen" item with no Sipser citation — the deck's figure traces to Hennie's 1965 paper).

Crossing-sequence proof — the idea

  1. Splicing lemma: if Ci(x) = Cj(y), glue x's left part to y's right part — M can't tell the swap happened (all it learns across the boundary is that one state-list), so if x,y are accepted, the splice is too.
  2. The trap: build L_n = { w #n/2 wr } — 2n/4 genuine palindromes. If two different ones ever shared a crossing sequence in the middle "#" band, splicing gives a non-palindrome M would wrongly accept. So all of them need pairwise-disjoint crossing sequences there.
  3. Counting squeeze: only |Q| states exist (fixed), so fitting 2n/4 distinct sequences forces the sequences to be long: shortest one needed is already Ω(n).
  4. Conclusion: some word forces every crossing sequence across the Θ(n)-wide middle band to be Ω(n) long → total steps ≥ Θ(n)·Ω(n) = Ω(n²).

7 · Non-deterministic Turing Machines

slides II-81–97 · Sipser §3.2 / §7.1

The one change: δ is a relation

δ ⊆ Q×Γ×Q×Γ×{←,□,→} — for one (state, symbol) pair, several rules can apply at once; the machine may follow any of them. Think DFA vs NFA.

Two different quantifiers — don't blur them

  • Accept = some branch reaches accept (existential — one lucky path is enough)
  • Decider = every branch halts (universal — all of them, no exceptions)
  • time_M(w) = the max over every branch (not just the accepting one)

Equivalence (power) and the cost (time)

Same languages decidable as a normal TM — but simulating one deterministically costs roughly 2t(n) instead of t(n). Idea: 3 deterministic tapes (clean input copy · scratch tape for trying one path · an "address" tape naming which path), enumerated shortest-path-first (breadth-first) so a short accepting path is never missed behind an infinite one.

P and NP, in one paragraph

P = decidable in polynomial time by a normal TM. NP = decidable in polynomial time by a non-deterministic TM — equivalently, "yes" answers have a short proof/hint a normal TM can check fast. P ⊆ NP always. Whether P = NP is open — the biggest unsolved question in the field. This exponential NTM-simulation gap is that question in miniature: find a much better simulation, and you've resolved it.
